مِرصاد V17 — المرحلة الخامسة: الأمان والمراقبة والنسخ الاحتياطي
نطاق الحزمة
هذه رقعة تكميلية تبنى على المرحلة الرابعة وتحديث التشغيل الجماعي الأخير؛ لا تستبدل محرك RapidAPI أو ملف core.py.
ملفات النشر على GitHub:
`app.py`: إضافة صفحة «الأمان والمراقبة» إلى قائمة الإدارة اليمنى، وتنظيم اختبار صحة SQLite، وإنشاء نسخة احتياطية قابلة للتنزيل، وإضافة مهلة حماية 5 دقائق بعد خمس محاولات دخول خاطئة في الجلسة نفسها.
`ops_health.py`: فحوص سلامة SQLite، عداد سجلات، ملخص الحالات، والتحقق من بعض إعدادات الحماية دون عرض الأسرار.
`ops_backup.py`: نسخ SQLite بتقنية Backup API المتسقة مع وضع WAL، والتحقق من integrity_check قبل تنزيلها.
`restore_backup.py`: استعادة خارج الموقع إلى مسار قاعدة بيانات جديد فقط بعد التأكيد.
`test_phase5.py`: اختبار محلي، لا تنشره بالضرورة إلى الموقع.
التثبيت
خذ نسخة احتياطية آمنة من المشروع وقاعدة البيانات قبل التغيير. لا تنشر ملف SQLite في مستودع عام.
استبدل `app.py` وأضف `ops_health.py` و`ops_backup.py` إلى جذر مستودع مِرصاد. احتفظ بملفات المرحلة الرابعة الأخرى.
احتفظ بـ `restore_backup.py` خارج الموقع في جهاز الإدارة، ولا يلزم رفعه إلى GitHub. لا تضع مفاتيح API داخل الملفات.
اضغط Commit changes ثم افتح الموقع، وسجّل الدخول، وانتقل إلى «🛡️ الأمان والمراقبة».
أنشئ نسخة احتياطية، نزّلها، واحفظها مشفرة وفي مساحة خاصة. احذف النسخة المؤقتة من جلسة الواجهة بعد تنزيلها.
إن أردت التحقق من الاختبارات: `PYTHONPATH=. python test_phase5.py` (يتطلب ملفات V17 الأساسية).
استعادة قاعدة البيانات خارج الموقع
أوقف الموقع والعامل الخلفي أولًا، ثم نفذ في مجلد المشروع:
```bash
python restore_backup.py ./mirsad-backup-YYYYMMDD-HHMMSS.sqlite3 ./restored-mirsad.sqlite3 --confirm
```
بعد النجاح، غيّر `MIRSAD_DB` إلى مسار الملف الجديد على قرص دائم، ثم أعد تشغيل عامل المهام والموقع. الاستعادة لا تكتب فوق قاعدة موجودة ولا تغيّر ملف المستخدم تلقائيًا.
حماية أسرار API
ضع `ADMIN_PASSWORD` و`RAPIDAPI_KEY` داخل Streamlit Secrets أو متغيرات بيئة آمنة، وليس ضمن GitHub أو صور الأخطاء أو ملف ZIP.
إذا سبق نشر مفتاح RapidAPI أو كلمة المرور، ألغِ القديم وولّد مفتاحًا/كلمة مرور جديدين.
حد محاولات تسجيل الدخول الحالي على مستوى جلسة المستخدم فقط؛ يمكن تجاوزه بإنشاء جلسة جديدة. الحماية الإنتاجية تتطلب مصادقة خارجية مع حد طلبات على مستوى الخادم أو خدمة هوية.
النسخ الاحتياطية غير مشفرة تلقائيًا؛ التخزين المشفر وإدارة الاحتفاظ مسؤولية مسؤول المنصة.
نطاق الاختبارات والقيود
تم اختبار إنشاء 10 ثم 50 ثم 100 مهمة محلية افتراضية، وفحص SQLite، ونسخة اتساق WAL، والاستعادة إلى مسار جديد، ورفض الكتابة فوق قاعدة موجودة، واستمرار نجاح اختبارات المرحلة الرابعة للتقارير.
ليس هذا اختبار تحميل حي لـ100 حساب عبر RapidAPI، ولا ضمانًا لسرعة الخدمة أو تكلفة API.
هذا الإصدار لا يضيف مراقبة لحظية خارجية، أو تنبيهات بريدية، أو نسخًا احتياطية مجدولة، أو PostgreSQL، أو تخزينًا دائمًا على Streamlit Cloud. لا تعتمد على المجلد المحلي للاستضافة في حفظ متابعي X على المدى الطويل.
مؤشرات الصحة لا تعرض بيانات المتابعين ولا مفاتيح API، لكن الوصول للصفحة يجب أن يظل للمسؤول فقط.
